---

## 1. 项目定位

本项目是一个面向中小企业老板和营销负责人的一体化 AI 营销执行工具，核心目标是把“营销诊断”变成“可执行的每周任务”。

产品主线只有一条：

企业信息输入 → 诊断报告 → 7 天执行清单 → 老板执行 → 上传复盘数据 → 生成下周建议

这条链路是整个项目的唯一核心价值，任何不服务该链路的功能都不应作为主线开发重点。

---

## 2. 产品目标与用户

### 2.1 目标用户
- 小型实体店主
- 家装、餐饮、教育、美容、房产中介等行业的经营者
- 了解业务、但不擅长营销执行的人

### 2.2 核心价值
- 帮助用户快速发现营销短板
- 将诊断结论转为每日可执行任务
- 通过复盘优化下周执行方向
- 让用户从“想做”变成“能做”

---

## 3. 核心业务链路

### 3.1 诊断模块
- 用户提交企业基本信息
- 系统输出营销诊断报告
- 报告包含：综合评分、问题点、策略方向、本周聚焦事项

### 3.2 执行模块
- 读取诊断报告内容
- 生成 7 天执行清单
- 每日任务包含：任务标题、执行方式、检查项、完成标准、预计耗时

### 3.3 复盘模块
- 用户上传本周执行截图或 CSV 数据
- 系统解析数据并生成复盘报告
- 输出下周优化建议，供下一轮执行计划使用

---

## 4. 当前技术架构

### 4.1 总体架构

```text
微信小程序前端 → FastAPI 后端 → AI Agent / 规则引擎 → 数据持久化
```

### 4.2 前端架构
- 技术栈：原生微信小程序 + TypeScript
- 入口：miniapp/app.ts 与 miniapp/app.json
- 页面目录：miniapp/pages
- 可复用组件：miniapp/components
- 统一请求封装：miniapp/api/request.ts

### 4.3 后端架构
- 技术栈：Python + FastAPI
- 入口：src/api/main.py
- 核心模块：
  - src/agents/diagnosis.py：诊断 Agent
  - src/agents/executor.py：执行引擎 Agent
  - src/agents/reviewer.py：复盘 Agent
- 业务模型：src/models
- Prompt 模板：src/prompts
- 服务层：src/services

### 4.4 AI 与规则引擎
- 优先走 LLM 生成结果
- 如果模型不可用或返回数据不合法，则回退到规则引擎
- 这样能保证在无 API Key 的环境下仍可完成基础流程

## 7. 开发原则

1. 以“诊断 → 执行 → 复盘”一条主链路为中心。
2. 优先保证业务闭环，而不是堆砌功能。
3. 小程序前端保持轻量、清晰、易操作。
4. 后端 Agent 需支持 LLM 与兜底规则两种模式。
5. 文档内容应与当前代码结构保持一致，避免长期漂移。

---

## 8. 推荐开发顺序

1. 先确保后端诊断、执行、复盘流程可跑通
2. 再完善小程序页面与接口联调
3. 最后补齐测试、数据校验、异常兜底

### 后端

- 启动方式：使用 Uvicorn 或项目说明中的命令

### 小程序
- 入口：miniapp/app.ts 和 miniapp/app.json
- 通过微信开发者工具导入项目根目录运行

---

## 10. 结论

这是一套以“AI 营销执行闭环”为核心的微信小程序 + FastAPI 项目，当前已经具备完整的产品骨架与开发基础。后续重点应放在以下三点：

- 让诊断结果更稳定、更易懂
- 让执行计划更贴近真实业务
- 让复盘反馈更容易驱动下一周优化
